# 02 常见建模套路

> 面向第一次参加 MCM/ICM 的同学。本章不追求“背算法”，而是训练一条完整证据链：**题意 → 变量 → 假设 → 关系 → 模型 → 求解 → 检验 → 改进 → 结论**。

## 先说明：什么是“套路”

这里的“套路”不是看到关键词就套公式，而是反复出现的**问题结构**。同一个“分配”问题，可能因公平要求变成多目标优化，因需求未知变成稳健优化，因决策分阶段变成随机规划。模型名称不是起点，题目的决策、目标、约束和数据才是起点。

## 建议阅读顺序

1. 先读[模型选择与通用工作流](00_模型选择与通用工作流.md)，学会把自然语言翻译成数学问题。
2. 根据题目要回答的问题进入五大类之一，先看该类的 `README` 对比表。
3. 阅读具体模型时，优先掌握“基础模型”和“改进阶梯”，代码可交给 AI 辅助实现。
4. 最后必须做检验；没有误差、敏感性或稳健性分析的复杂模型，通常不如一个被充分验证的简单模型。

## 每篇主题的统一结构

- **问题识别**：何时适用，何时不要用。
- **模型建立**：对象、变量、参数、假设、核心公式。
- **求解流程**：强调逻辑与输出，不堆代码。
- **改进阶梯**：基础模型怎样逐层贴近现实。
- **检验清单**：怎样证明结果可信。
- **论文表达**：论文里应展示什么，而不是只报告一个数。
- **AI 协作**：让 AI 写代码前，必须提供哪些建模信息；拿到结果后怎样审查。

## 三条底线

1. **不能用更复杂替代更合理。** 模型必须服务于问题，不为“高级”而高级。
2. **不能把求解成功当作建模正确。** 程序能运行，只说明公式被执行，不说明假设、数据和公式正确。
3. **不能只报最优值或准确率。** 同时报告可行性、误差/区间、敏感性、现实含义和局限。
