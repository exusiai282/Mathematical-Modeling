# 模型选择与通用工作流

## 1. 先判断“题目要你交付什么”

不要先搜索模型名。把每个子问题压缩成一句话：

> 在给定的 **对象与范围** 内，利用 **哪些数据**，决定/估计 **什么量**，在 **哪些限制** 下，使 **什么标准** 更好，并用 **什么方式验证**。

由核心动词初步判断：

| 核心动词 | 常见结构 | 仍需追问 |
|---|---|---|
| 分配、安排、选择、规划、最小化 | 优化 | 决策变量能否控制？约束是什么？ |
| 评价、排序、分级、优选 | 评价决策 | “好”的定义是什么？权重从哪里来？ |
| 预测、估计未来、趋势外推 | 预测 | 时间顺序是什么？预测期限多长？ |
| 分群、识别、判别 | 聚类/分类 | 是否已有标签？类别是否需要解释？ |
| 传播、扩散、级联、关键节点 | 传播/网络 | 接触关系是否重要？状态怎样转移？ |

关键词只能用于初筛。例如题目说“预测最佳政策”，前半部分可能是预测，后半部分仍是优化；应先预测需求，再把预测值或情景送入优化模型。

## 2. 一张表完成问题数学化

建模前为每个子问题填写下表：

| 项目 | 要回答的内容 | 自查问题 |
|---|---|---|
| 对象与边界 | 研究谁、何时、何地 | 是否把系统边界说清楚？ |
| 输入 | 原始数据、外部参数 | 单位、时间频率、来源可靠吗？ |
| 输出 | 排名、预测值、方案或曲线 | 是否逐项对应题目要求？ |
| 决策变量/未知量 | 模型需要求什么 | 是可控制决策，还是待估参数？ |
| 目标/评价标准 | 什么叫“更好” | 是否可度量、方向明确？ |
| 约束/机制 | 必须满足的现实规律 | 容量、守恒、逻辑、时间关系齐全吗？ |
| 不确定性 | 哪些量并非确定 | 用区间、分布还是多情景表达？ |
| 验证 | 如何判断可信 | 有历史数据、基线、极端情形或专家常识吗？ |

## 3. 建立“最小可用模型”

先建立能闭环回答问题的最简单版本：

1. **定义集合和索引**：对象、地点、时间、类别。
2. **区分三类量**：已知数据、待估参数、决策变量。
3. **写假设并说明用途**：每条假设都应对应一个简化或公式。
4. **写核心关系**：目标函数、约束、状态转移、统计关系或评价映射。
5. **检查量纲**：相加的量必须同维；指数函数的指数通常应无量纲。
6. **检查边界**：概率在 $[0,1]$，人数非负，资源不能凭空增加。
7. **列出预期输出**：主结果、图表、诊断与建议。

最小模型的作用是提供基线。只有先得到基线，才知道后续改进究竟带来了什么。

## 4. 改进模型：一次只解决一个明确缺陷

推荐沿以下顺序递进，而不是同时堆叠算法：

### 第一级：数据更真实

- 统一单位和时间粒度；处理缺失值、异常值。
- 将合计数据细分到必要的群体、地点或时间。
- 检查样本偏差和数据泄漏。

### 第二级：机制更真实

- 加入容量、时间窗、空间距离、非线性、滞后或网络关系。
- 放松过强假设，如“所有个体完全相同”“参数始终不变”。
- 让参数可随时间、情景或群体变化。

### 第三级：处理不确定性

- **情景分析**：乐观/基准/悲观，最容易解释。
- **敏感性分析**：观察关键参数扰动是否改变结论。
- **蒙特卡洛模拟**：已知或可假定参数分布时使用。
- **稳健/随机优化**：不确定性会直接改变决策时使用。

### 第四级：处理多方目标

- 同时考虑成本、效果、公平、风险和可执行性。
- 展示 Pareto 权衡，而不是隐藏在一个随意的加权分数里。

每次改进都要回答：**基础模型的哪个缺陷被修复？新增了什么数据或假设？指标改善多少？结论是否改变？**

## 5. 验证不是一个指标，而是五层证据

| 层次 | 检查内容 | 常用方法 |
|---|---|---|
| 公式验证 | 数学和实现是否一致 | 手算小样例、守恒/边界检查 |
| 数据验证 | 输入是否可靠 | 来源核对、描述统计、异常检查 |
| 拟合/预测验证 | 对未见数据是否有效 | 留出集、滚动验证、交叉验证 |
| 结构验证 | 机制是否符合常识 | 极端情形、单调性、专家判断 |
| 决策验证 | 建议是否稳定可行 | 敏感性、稳健性、情景压力测试 |

对优化问题，至少重新代入检查全部约束；对预测问题，必须与简单基线比较；对评价问题，要检查权重和标准化变化是否颠覆排序；对传播模型，要检查总量守恒和参数可识别性。

## 6. 模型选择的证据写法

论文中不要只写“该模型效果很好，因此采用”。建议用四句话：

1. 题目结构：需要解决的决策/关系是什么。
2. 数据条件：现有数据支持估计哪些量。
3. 模型匹配：该模型的变量、机制或输出怎样对应题目。
4. 取舍说明：相对备选模型，它牺牲什么、换来什么。

示例：

> 该子问题要求在总预算和各地区容量限制下确定投放量，决策变量连续且收益可近似线性。因此先建立线性资源分配模型，以获得可解释的基准方案。考虑到需求预测存在误差，随后在多个需求情景下进行压力测试，并加入最低服务比例约束改善公平性。

## 7. 与 AI 协作的正确分工

### 交给 AI 之前，你必须决定

- 集合、索引、单位和时间范围；
- 决策变量或预测目标；
- 目标函数、约束或状态转移逻辑；
- 数据划分与验证方式；
- 需要输出的表和图。

### 可让 AI 辅助

- 把已确认的公式实现为代码；
- 生成数据清洗、求解、绘图和批量实验流程；
- 检查变量维度、约束遗漏和潜在数据泄漏；
- 为不同参数自动做敏感性实验；
- 将结果整理为表格，但结论必须人工复核。

### 通用提示词模板

> 请按以下已确定的数学模型实现并验证，不要自行更改模型含义。先复述集合、变量、参数、单位、目标函数/状态方程和约束；指出信息缺口后再写代码。代码必须包含：输入检查、固定随机种子、一个可手算的小样例、约束或守恒校验、基线对比、核心结果表、敏感性分析。若求解不可行或指标异常，不要伪造结果，请输出诊断信息。

### 拿到 AI 代码后的六问

1. 变量索引和数据列是否一一对应？
2. 正负方向、单位、比例与百分数是否混淆？
3. 训练集是否偷看了测试期或未来信息？
4. 优化结果是否真的满足每一条约束？
5. 随机算法是否固定种子并重复实验？
6. 图表和结论能否由原始输出重新计算得到？

## 8. 论文中建议保留的最小证据包

- 一张模型框架图；
- 一张符号表；
- 一组完整的核心公式与解释；
- 一张参数来源/估计方式表；
- 一张主结果表和一幅关键图；
- 一个基线或备选模型对比；
- 一组敏感性、稳健性或误差结果；
- 一段局限性与适用边界。

这套证据包比大量没有解释的代码、公式和算法名更有说服力。
