# 04 AI 辅助代码

建模中写代码是新手最头疼的部分。AI 可以帮助生成代码框架、排查 bug、解释报错，但 **AI 生成的代码必须自己跑一遍并验证结果**。所有代码在交论文前都要能复现。

## 1. 生成代码提示词

**方法论：** 让 AI 生成代码时，描述越具体，代码越可用。关键信息包括：**输入数据格式**（列名、数据类型）、**期望的输出**（什么样的图/表/数值）、**使用什么库**（如 Python 的 numpy + scipy + matplotlib）、**变量命名约定**。不要只说"帮我用 TOPSIS 评价"，而要给出数据样本和具体的评价指标。

**提示词模板：**
```
请帮我编写 Python 代码，实现以下功能。

【需求描述】
[用自然语言描述你要实现什么，如：用熵权法计算各指标权重，再用TOPSIS法对20个方案进行综合评价排序]

【输入数据】
- 数据文件：Excel文件 "[文件名].xlsx"，位于Sheet "[表名]"
- 数据结构：第一行为指标名，第一列为方案名，其余为数值
- 数据规模：[ ] 行 × [ ] 列
- 指标方向：正向指标有 [列出列名/列号]，负向指标有 [列出]
- 特殊说明：[如：第一列是字符串格式的方案名称，不需要参与计算]

【输出要求】
1. 输出各指标权重（DataFrame 形式，包含指标名和权重值）
2. 输出每个方案的综合得分和排名（从高到低排序）
3. 生成一张得分排名柱状图（方案名作X轴，得分作Y轴）
4. 所有结果同时保存为 Excel 文件

【技术要求】
- Python 版本：3.9+
- 使用库：pandas, numpy, matplotlib, scipy（不要用我没装的库）
- 代码结构清晰，关键步骤加注释
- 数据路径使用变量，方便我修改
- 在代码开头检查文件是否存在，不存在则给出明确提示

【输出格式】
只输出可直接运行的完整 Python 代码，不要加额外的解释文字。
```

## 2. 检查代码提示词

**方法论：** AI 检查代码的重点不在于语法（语法错误你自己跑一遍就知道了），而在于 **逻辑正确性** 和 **建模层面的问题**——比如归一化范围对不对、正负向处理是否遗漏、边界条件是否考虑。检查时要把代码和模型设计一起给 AI，让它判断代码是否忠实实现了模型。

**提示词模板：**
```
请审查以下代码，从建模正确性和代码质量两个维度找出问题。

【模型设计要求】
- 模型名称与原理简述：[ ]
- 关键公式/步骤：[描述模型的核心计算流程]
- 特殊要求：[如：需要对负向指标先取倒数再归一化]

【待审查代码】
[粘贴完整代码]

请从以下角度逐项检查：
1. **建模正确性**
   - 算法步骤是否与模型原理一致？
   - 正负向指标处理是否正确？
   - 归一化/标准化方法是否合理？
   - 权重计算、排序逻辑是否正确？
   - 是否有遗漏的步骤或错误的公式实现？
2. **边界条件**
   - 数据为0、负数、缺失值时是否会崩溃？
   - 除零风险在哪里？
   - 极端值（全相同、全为0）时的表现是否合理？
3. **代码质量**
   - 是否有明显的性能问题（不必要的循环、重复计算）？
   - 变量命名是否清晰？
   - 是否有未使用的变量或未关闭的文件？
4. **结果验证**
   - 如何验证这段代码的输出是正确的？
   - 建议添加哪些中间结果打印来帮助排查问题？

请标注每个问题的严重程度（致命/严重/建议）。
```

## 3. 解释代码提示词

**方法论：** 新手常常从网上或 AI 那里拿到一段代码但看不懂。让 AI 逐段解释代码时，要求它 **说出每一步的数学含义**，而不仅仅是翻译代码语法。这样解释可以帮助你理解模型本身，也方便写论文时描述"模型求解过程"。

**提示词模板：**
```
请详细解释以下 Python 代码，要求：

【解释方式】
1. 先概括：这段代码整体做了什么（一句话）
2. 分块解释：按功能将代码分成几个块，每块说明：
   - 这块做了什么计算
   - 对应的数学操作是什么（公式或数学语言描述）
   - 输入和输出分别是什么
3. 关键变量说明：重要的中间变量代表什么含义

【特别注意】
- 解释时侧重数学含义而非编程语法
- 如果有我不熟悉的库函数，请特别说明其功能
- 指出代码中与模型假设或数据预处理相关的关键部分

【代码】
[粘贴代码]
```

## 4. 代码结果验证清单

**方法论：** 这是防止论文翻车的最后一道防线。代码能跑 ≠ 结果正确。你需要用"常识检验"来验证结果的合理性——比如数量级对不对、趋势合不合理、极端情况有没有出错。下面的清单不是给 AI 的提示词，而是你自己每次跑完代码后必须逐项检查的清单。

**验证清单（自查用）：**
```
□ 1. 数量级检查
   - 结果的数值量级是否符合常识？（如预测房价不应出现负数或百亿，评分应在0-100范围内等）

□ 2. 趋势一致性检查
   - 如果有多个方案/样本，排序是否大致合理？
   - 如果更改一个输入变量的值，输出的变化方向是否符合预期？

□ 3. 边界测试
   - 选取一个极端情况（如全0、全最大值），手动推算预期结果，对比代码输出
   - 将某个输入值翻倍，观察输出变化是否合理

□ 4. 可复现性
   - 重新运行一遍代码，结果是否完全一致？（涉及随机数时是否设置了随机种子？）

□ 5. 数据溯源
   - 每个输出的数字，你能清楚地追溯其来源吗？（来自哪个文件、哪一步计算）
   - 如果评审老师问"这个0.784怎么来的"，你能答出来吗？

□ 6. 代码-论文一致性
   - 论文中引用的所有数值，代码中是否都有对应输出？
   - 论文中的图表，是否都由代码生成（而非手工绘制）？

□ 7. 假设验证
   - 代码运行依赖的假设（如数据正态分布、线性关系），你是否验证过？
   - 如果假设不成立，结果可能偏差多大？
```
