# 05 AI 使用风险

AI 是双刃剑，用好了事半功倍，用不好可能直接导致论文被质疑甚至取消成绩。以下风险按严重程度排序，请务必在每次使用 AI 后自查。

## 1. 防止模型乱编

**风险说明：** AI 最危险的行为是 **"幻觉"（Hallucination）**——自信地输出看起来很专业但完全错误的内容。典型表现包括：编造不存在的参考文献、编造看起来很合理的公式、编造没有依据的数据结论。新手最容易踩的坑是：这道题 AI 看起来说得头头是道，就全盘接受了。

**防范方法：**
- **公式逐一验证**：AI 给的每条公式，必须自己在草稿纸上推导一遍或用简单数据代入检验。特别注意下标、求和范围、条件分段的正确性。
- **参考文献绝不直接用**：AI 输出的任何参考文献（论文标题、作者、期刊）大概率是编的，除非你能在知网/Google Scholar 上找到原文。
- **事实陈述要交叉验证**：AI 说的"根据XX理论""一般认为XX"，必须自己查资料确认，不能直接写进论文。
- **警惕过于完美的答案**：如果 AI 给你的模型方案看起来无懈可击、没有任何困难和取舍——它很可能在掩盖问题。

**自查话术（对 AI 反问）：**
```
请对你刚才给出的建议/公式/结论，逐条说明其来源和依据。如果某条建议是你基于通用知识生成的（而非基于我提供的题目信息），请明确标注。对于任何你不确定的内容，请用"以下是推测，需要验证"开头。
```

## 2. 防止数据来源虚假

**风险说明：** 竞赛中经常需要外部数据（如人口统计、经济发展数据、行业标准参数等）。AI 可能会编造看起来很合理的数据，或者给出来源但实际找不到。**用假数据 = 论文核心结果无法被信任**，这是致命问题。

**防范方法：**
- **外部数据只用可溯源的**：所有非题目提供的数据，必须注明真实来源（国家统计局、世界银行、权威论文等），并在论文中附上引用。
- **AI 给的数据要还原验证**：如果 AI 说"根据XX年鉴，2020年某指标为YY"，你必须找到该年鉴核验。
- **标准参数不要问 AI**：像重力加速度、标准大气压这类常数，直接查教材或标准手册，不要问 AI。
- **优先使用题目附带数据**：非必要不引入外部数据，减少风险敞口。

**安全的做法：**
```
需要外部数据时，让AI帮你列出"可能需要的数据"和"建议去哪里找"，
而不是直接让它给你具体数值。

正确提示词：
"基于本题，我需要哪些外部数据来支撑模型？请列出数据类型、
可能的来源（如国家统计局网站、世界银行数据库、公开论文等），
但不要给出具体数值——我会自己去查。"
```

## 3. 防止公式错误

**风险说明：** AI 生成公式时常见的问题：符号定义不清楚、下标范围错误、混淆不同模型的公式、自创看起来很合理的"变体"。尤其是当你把两个模型的描述混在一起给 AI 时，它可能把 A 模型的公式接在 B 模型的框架上，产生"混血错误"。

**防范方法：**
- **每个公式必须手推一遍**：不要求严格数学证明，但要用一组简单数据代入验证公式的输入输出是否合理。
- **注意符号一致性**：AI 可能在同一段文字中对同一个量使用不同符号（如上标和下标混用），仔细检查。
- **检查公式的"适用条件"**：很多数学公式有适用条件（如"当 n→∞"、"假设X服从正态分布"），AI 可能不提条件直接给公式，你需要确认条件在你的场景下是否成立。
- **不要堆砌公式**：AI 有时会为了看起来"专业"而堆砌不必要的高级公式。你论文里的每个公式都应该是必要的——能解释、有计算、出结果。

**自查话术（对 AI 追问）：**
```
请逐一检查你给出的每条公式：
1. 这个公式的适用前提是什么？在本问题中是否满足？
2. 公式中每个符号的定义是什么？单位是什么？
3. 这个公式和你前面给出的其他公式之间，符号是否一致？
4. 请给出一组具体数值代入这个公式，展示计算过程以验证其合理性。
```

## 4. 防止英文空泛

**风险说明：** 美赛论文中 AI 生成内容的典型问题是 **"fluent but empty"（流利但空洞）**——读起来很顺，但没有实质信息。比如通篇 "our model performs well" 但没有任何具体数据支撑；"this approach has significant advantages" 但不说优势是什么。这种论文很容易被评委识破为 AI 生成，从而导致降档。

**防范方法：**
- **每个概括性陈述后面必须跟具体数据**：AI 写了 "the results demonstrate high accuracy"，你自己补上 "with an R² value of 0.94 and MAPE below 5%"。
- **删除所有"万能句"**：如 "This model can be widely applied in various fields"、"Our method provides valuable insights"——这些说了等于没说的话，全部删掉。
- **AI 生成 → 你注入数据 → AI 再润色**：正确的工作流是两轮：第一轮 AI 生成草稿 → 你填入具体数据 → 第二轮 AI 润色数据和文字的整体表达。
- **控制 AI 帮你写的比例**：核心段落（模型创新、关键结论）最好自己手写英文或用中文写好再让 AI 翻译优化，不要从零让 AI 生成。

**自查清单：**
```
□ 每个 "good/high/significant/robust" 后面是否跟了具体数字？
□ 每个结论是否有数据或逻辑支撑？
□ 是否有句子去掉后不影响论文信息量？
□ 核心贡献段落是否由自己主导写就（而非AI从零生成）？
□ 读一遍论文，问自己"如果我是评委，能从这篇论文中学到什么具体的东西？"
```

## 5. 防止代码结果不可解释

**风险说明：** 代码跑出结果不等于你能解释结果。竞赛中可能出现：AI 生成了一段复杂代码，你跑了，出了结果，但评委问"这个参数是什么意思？为什么选这个值？"你回答不了。**不能解释的结果 = 无效结果**。

**防范方法：**
- **确保自己理解每一步**：用前面 04.3 节的提示词让 AI 解释代码，直到你能用自己的话讲清楚整个计算流程。
- **关键参数要能论证**：代码中的所有参数值（如学习率、聚类数K、正则化系数），都要能在论文中说明"为什么选这个值"（可以通过调参实验、参考文献、或经验法则说明）。
- **保留调参过程**：如果你尝试了多组参数，保留对比结果，这不仅帮助你在论文中展示严谨性，也让你真正理解参数的影响。
- **代码要自己从头跑一遍**：不仅仅是按"运行"按钮，而是打开代码文件，逐段执行，检查中间变量是否符合预期。如果你连中间结果的样子都没见过，那你并不"懂"自己的代码。

**养成习惯：**
```
每次AI生成代码后，执行以下流程：
1. 让AI解释代码（用04.3提示词）
2. 自己逐段运行，打印中间结果
3. 修改一个你理解的小地方（如换个颜色、调整一个参数值），确认代码按预期变化
4. 用一组你能手动推算的简单数据测试代码，对比手动结果和代码输出
5. 确认完毕后，将理解后的代码逻辑用自己的话写进论文的"模型求解"部分
```
